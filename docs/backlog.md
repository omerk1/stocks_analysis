- **#16, #17, #21, #28, #29** — **Diagonal candidate generation & dedup: five rounds of real-chart-review fixes.** Each found by comparing detection output against real AAPL/T/PAAS/GEVO charts, not synthetic cases. Dedup checked pivot-overlap instead of actual slope/price proximity, so a clean 3-touch AAPL trendline was discarded as a false "duplicate" of unrelated lines (#16, also raised `diagonal_max_candidates` 30→300); replaced with a real price-proximity check (#17a), which also surfaced a deeper bug where merged-in events were displayed against the wrong geometry, up to 49.6% off real price (#17b, fixed by re-classifying events from scratch on every merge). `first_touch` was incorrectly pulled backward past a diagonal's own fitted geometry on merge — now horizontal-only (#21). - **#18, #19** — **Scoring: two independent quality gaps closed.** `duration_density` normalized diagonal spans against the full 8-year detection window regardless of line kind, crushing genuinely strong recent trendlines (#18, now normalizes against a fixed 1-year reference). - **#20, #22, #23, #24, #25** — **The "hovering" bug and its full resolution arc**, across four progressively-deeper real-data investigations into diagonal lines that looked disconnected from real price. `in_play_gate` split out as its own multiplicative gate so a line maxed on touch_quality/resilience/role_reversal couldn't buy back a genuinely disconnected position (#20). That gate itself averaged over a line's *entire* history, unable to tell a spurious fit from a real trendline with an ordinary multi-year dormant gap before a legitimate breakout — fixed with `scoring.regime_start()`, scoping evaluation to the line's current regime (#22). Self-corrected an overreach where `regime_start` also (wrongly) truncated the *rendered* box, hiding real multi-year trendline shape — reverted to `first_touch` for rendering, kept `regime_start` for scoring only (#23). `touch_quality`/`resilience`/`role_reversal` still saturated within a long *continuous* regime (no gap for `regime_start` to catch) purely from event count — fixed with `_most_recent(events, k)`, windowing all three to their k most recent qualifying events; saturation rate dropped from 9-14/15 to 0-2/15 across AAPL/PAAS/T's real top-15 lines (#25). Full log: `docs/sr_lines_design_notes.md`.
- **#26, #27** — **Chart marker rendering fixes, found from real chart screenshots, not code review.** BREAK markers were drawn at the event's resolution bar instead of the actual crossing bar, reading as floating during a continuing breakdown — now drawn at the crossing bar, consistent with the break/flip annotations (#26). Event markers were always rendered fully bold/full-size regardless of their own line's strength, so a weak line's markers stood out as bold orphans once its box faded into the near-invisible background — markers now fade opacity/size with line strength the same way the box already does (#27).

- **#30** — **Weekly-bar detection mechanism, plus two duration_density fixes found while reviewing it** (`feature/sr-lines-weekly-bars`). Resamples live from `bars_1d` via the already-tested `data_processing.resample.to_weekly`, not the separately-ingested `bars_1w` (incomplete for several tickers, and found to sometimes carry not-yet-finalized data — same partial-row filtering discipline needed either way, so live resampling has no real downside). Caught and fixed a real lookahead bug in the process: week-closure was judged against wall-clock "now" instead of the data's own latest timestamp, which could let an under-ingested week read as closed (confirmed on real PAAS data, 3 days of local ingestion lag). Config redesigned twice after direct feedback — from a mutate-in-place function to four fully explicit, independent presets, nothing derived or patched. Reviewing the mechanism's real output surfaced `duration_density` normalizing diagonal spans against a fixed 1-year reference but horizontal against the full detection window — any diagonal older than 1 year auto-maxed this component while a horizontal needed the entire window to do the same, letting a sparse-evidence diagonal outrank a better-evidenced horizontal on a real PAAS chart. Fixed: both kinds now use `window_years/3`, verified byte-identical to the old diagonal-only formula at medium_term across 2,509 real diagonals on a random 20-ticker sample. A second gap found in the same review — the span-only formula let any sparse-but-old line max out regardless of how populated its span actually was (17 of 3,314 real lines on the same sample) — got a cheap density-factor fix; a related, initially-suspected touch_quality/role_reversal divisor issue was investigated and *not* changed after the real data (28,789 real touch reactions) didn't support the suspicion. 181 tests passing. Full log: `docs/sr_lines_design_notes.md`.
