## In progress / open questions

- **sr_lines, still open** (grouped since they're all part of the same ongoing review — full detail in `docs/sr_lines_design_notes.md`):
  - `in_play_gate` is only *partly* fixed. `regime_start` (Done #22/#24/#25) fixed averaging over a line's entire history; still not fixed: it's one flat average *within* the current regime, so it can't tell "scattered near-misses" from "one solid contiguous block of disconnection." Likely needs a max-contiguous-out-of-play penalty, not a different average.
  - Milestones 6 (`as_of` test coverage) and 7 (systematic weight-tuning pass) still ahead. Carried-forward calibration questions: `resilience`'s cap can still be hit by enough recent events; wick-fake vs. body-fake resilience credit may be inverted from real-world evidence-strength (as of Done #35, whether `BODY_TOUCH` should also earn resilience credit is the same open question, now with a third type in the mix); why `--dedup-threshold` affects diagonal clutter much less than horizontal.
  - **Weekly-bar mechanism shipped (Done #30), calibration still open**: the three original bar-count-denominated config knobs (`fakeout_reclaim_bars=1`, `touch_reaction_window_bars=2`, `diagonal_min_pivot_separation_bars=4`) — plus, as of Done #35, `max_diagonal_slope_atr_per_bar=1.75` for the same reason — are a first-pass starting point, not yet validated against real weekly charts.
  - **sr_lines now persists to `analysis.sqlite` (Done #35) but, like the four newer modules, hasn't been run against the full ticker universe yet** — only ad-hoc/smoke-test tickers so far. A resumable bulk-detection pass is the same still-open item as the one below for gaps/divergences/fibonacci/avwap; sr_lines could share it once built.
  - **Milestone-7 tuning pass candidates newly available from Done #35's raw data, not yet analyzed**: `penetration_trend`, `slope_atr_per_bar`, and the new touch/break/age fields are all stored but not wired into `ScoreBreakdown`/`score_line` — worth a real-data pass to see whether any of them should be.
- Whether/how to source quarterly financials — still gated behind an undecided Polygon paid tier.
- **Historical shares-outstanding (Done #31), follow-up not yet done**: the bulk backfill hasn't been run against the full active universe yet (held for explicit go-ahead — real API-cost/rate-limit operation).
- **Four new TA modules (Done #33) — gaps/divergences/fibonacci/avwap — are built but not yet run against the full ticker universe.** Each only has ad-hoc/smoke-test data in `data/derived/analysis.sqlite` so far; a resumable bulk-detection pass (mirroring `bulk_ticker_metadata_ingest.py`'s pattern) hasn't been built or run. Also open, from the original spec's own explicit backlog: gap↔sr_lines / fib↔sr_lines confluence, inverse FVGs, hidden/triple-pivot divergences, AVWAP stdev bands, unifying AVWAP cycle anchors with fib swings, a dedicated backtest iterator API. **The comprehensive-output-model effort (making each module's stored output a full account of what the detector observed, not a lossy summary — same motivation as sr_lines' Done #35) is now fully done: fibonacci Done #36, avwap Done #37, divergences Done #38, gaps Done #39.**
- **Divergence confluence (Done #44) reports `confluence_count`/`agreeing_indicators` but doesn't feed `strength` — a data-driven call, not made yet.** `strength`'s weights are already tuned; boosting it for confluence would mean picking a bonus with no evidence behind it. The right test instead: correlate `confluence_count` against the outcome fields already stored per divergence (`max_favorable_move_atr`, `invalidated` — populated by `lifecycle.apply_outcome`) to see whether higher-confluence divergences actually resolve more favorably, same empirical approach as the gap fill-percentage script (Done #43). Held for now — divergences has only been run against ad-hoc tickers (AAPL/T/GEVO), too thin a sample for a real correlation; worth revisiting once/if a fuller-universe backfill exists (see the still-open bulk-detection item above).
- **Macro/meta-financial data ingestion is FRED-only for now (see `docs/done.md`).** Treasury-direct (`api.fiscaldata.treasury.gov`), BLS-direct, and BEA-direct were all confirmed live/free during validation but deliberately not integrated — FRED already re-hosts the headline series each of them would provide (full Treasury curve, CPI/PPI/employment, GDP/PCE detail), so a second source is only worth adding later if a specific granular series FRED doesn't carry is actually needed. Stooq was tried and dropped — its CSV endpoint is now behind a JavaScript proof-of-work bot challenge, not the plain download it once was. Also open: a resumable full-history bulk pull across `fred_client.CURATED_SERIES` (today's `fetch_macro.py` is a simple per-run loop, fine for ~18 series but no `fetch_jobs`-style resumability if one series' request fails mid-run).
- **Point-in-time-safe macro join (Done #45) has no consumer yet.** `market_common.macro.as_of_join` exists, is tested, and is hand-verified against real data (joining `UNRATE` onto AAPL's `bars_1d` dates correctly withholds each month's reading until its real `published_at`) — but nothing in the repo actually calls it. Wiring macro data into an actual TA module or backtest (e.g. as a `divergences`/`sr_lines` context feature, or feeding the confluence-vs-outcome correlation noted above) is a separate, still-open item.
