- **#41** — **Intraday-range-vs-ATR data-quality check** (found via sr_lines but not sr_lines-specific — closes the `docs/backlog.md` item). The existing `validate_bars` soft check only compares close-to-close, so a bar that spikes intraday and fully round-trips by the close was invisible to it; confirmed directly against real data first (T's 2023-01-24 bar: open 15.69, high 17.81, low 15.46, close 15.85 — high is ~13.5% above the open, but close-to-close vs. the prior day's 15.80 close is a completely unremarkable +0.3%). New soft check in `src/market_common/data.py`'s `validate_bars`: flags a bar whose `high - low` exceeds `3.0x` the *prior* bar's `ATR(14)` (prior, not the same bar's own ATR, so the spike can't inflate the very baseline it's measured against; reuses the existing `market_common.indicators.atr` helper, no reimplementation). Surfaced as a new `DataQualityReport.suspicious_intraday_range_dates` field, mirroring `suspicious_jump_dates`'s existing shape exactly — logged, not dropped. Threshold tuned against real data: T's 2023-01-24 ratio is 7.92x (T's own next-highest in ~16 years of history is 5.42x); spot-checked across 10 other real tickers spanning blue-chip (AAPL, MSFT, KO, JNJ, PAAS, MU) to high-volatility/meme names (GEVO, AMC, SMCI, TSLA) — `3.0x` flags roughly 0.1-1.3% of trading days per ticker, confirming it isn't tripping on every normal volatile day while still catching genuine outliers (some of which, like AMC's real 2021 short-squeeze day, are correctly-flagged real events, not data errors). 332 tests passing (3 new, including a real-data acceptance test against the actual stored T 2023-01-24 bar).

- **#41** — **Gap fill-percentage predictive-power analysis.** New standalone, read-only research script `src/analysis/gap_fill_predictive_power.py` (both DB connections opened in SQLite's own `mode=ro` URI mode — a write would fail at the sqlite3 layer, not just by convention). Corrected a stale backlog claim along the way: `fill_by` is NOT a `gaps` column (confirmed by reading `store.py`'s actual `_GAPS_SCHEMA`) — only `GapConfig`/`runs.config_json` carry it, so it's recovered here via a join on `run_id`. Reconstructs each stored gap's full per-bar fill-% time series by replaying `gaps.lifecycle._penetration_pct` (imported, not reimplemented) bar-by-bar from `created_at`, stopping once the running max first hits 100% (mirrors `_walk`'s own `n_approaches`-bounding reasoning — cummax can't move again after that). Correlates four fill-based signals (`peak_fill_pct`, `ever_closed`, `bars_to_threshold`, `bars_to_peak`) against direction-adjusted forward returns at two reference points (N bars after `created_at`, and N bars after the gap's own peak-fill bar) and several horizons (5/10/20/60 bars by default). Verified bar-for-bar against real AAPL data (not just "the script ran"): two real 2010 FVGs hand-computed from raw OHLC match the script's reconstructed series exactly (83.44%/65.22% at first touch, both resolving to 100% on the May 6 2010 flash-crash bar at bar-offsets 30 and 26) — pinned as an actual regression test (skipped, not failed, when local data isn't present). Result against the local universe (AAPL/T/GEVO, 2,124 of 2,126 gaps reconstructed): a real, statistically significant negative correlation between fill depth/completeness and subsequent direction-adjusted forward returns at every horizon tested (Spearman ρ ≈ -0.26 to -0.35, p < 0.001) — deeper/faster/more-complete fills tend to precede weaker continuation or outright reversal versus the gap's own original direction, not the other way around. Flagged honestly, not oversold: `peak_fill_pct`/`bars_to_peak` are computed from the gap's full resolution (however many bars that takes), so the from-creation reference point has a look-ahead overlap at short horizons when a gap closes within the window; the from-peak reference point avoids that specific overlap and shows materially the same negative relationship, which is the more trustworthy of the two. Only 3 tickers in the local universe, so this is a real but narrow-sample finding, not yet validated against the full universe. 350 tests passing (18 new, incl. the real-data regression test above).
